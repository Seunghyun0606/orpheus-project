# TASK-032 — Initial numeric ending balance proposal

Status: awaiting human approval, **not applied**. This is an initial trial for the
new unreleased complete campaign, not a claim of tuned fairness, passing QA or ten
reachable production endings. The exact weights, action groups, final states and
conditions are in
[the proposed data](../.project-os/planning/TASK-032.numeric-ending-balance-proposal.yaml).

## Proposed scoring contract

Keep the approved zero initial campaign values, but never initialize unavailable
behavior rates. The proposed values are authored game indices, not confidence,
population measurements or replacements for Incident resource accounting.

- Each of the eighteen new logical reveal nodes adds evidence/curiosity +1.
  The existing false-to-true logical guard prevents alias/re-investigation farming;
  merge deltas into that guarded effect rather than adding an order-dependent second
  effect. Six explicitly named human-system/accountability discoveries add public
  interest +2. The three MVP hints add curiosity only, not qualified major evidence.
- Genuine new completion of each INC-001–025 adds corporate alignment +1. Imported
  presence and inherited completions do not award it. INC-026 gives no positive
  ending-enabling credit.
- Each Incident's explicitly listed repair group adds safety +2 once; its temporary
  group adds safety -1 once. This describes cumulative operational exposure, not a
  moral right/wrong label for useful mitigation. Alternative repair actions share
  one receipt identity; trying both across retries cannot farm safety.
- One actual War Room update per INC-001–025 and one genuinely delivered team
  diagnosis per INC-004–025 add trust +1 each. Scheduling alone and repeated
  broadcasts do not create trust.
- Explicit send/withhold report actions add corporate +3/-1; sending also adds
  trust +1. Preserve/decline objective-copy actions add NULL alignment +3/-1.
  Each named direction is a separate once-per-run effect. These explicit action
  scores do not claim an opportunity observation without ACK.
- Each distinct positive verified recommendation response adds dependency +1,
  capped by its once-per-rule logical effect. THE BOARD requires all four distinct
  credits across three Acts, not four repeats or one acceptance. Negative/missing
  response gives no credit, not a fabricated rate or refusal.

The source inventory lists **55 explicitly operational actions in INC-001–025**
with exact content versions, targets and immediate costs. Fix their groups/weights
as data; do not infer future runtime scoring from category/name heuristics.

## Important damage-index limitation

For each distinct listed operational action, the proposed damage index adds
`ceil(explicit immediate CUSTOMER_IMPACT charge / 15)` once per Incident/action.
The ten terminal plans use the same explicit charge-based weights. Terminal damage
receipts are independent of the shared BLACKOUT_FINAL reveal flag, so changing
plans in later attempts retains the previous distinct plan's damage index.
Terminal choices add no evidence, alignment, safety, trust or dependency credit.

This is a **bounded distinct-choice index**, not total customer impact. Repeat
actions, elapsed time, investigation costs and delayed-event harm remain fully
recorded in the simulation/history but do not all enter this index. Actual final
service error, authority state and customer impact are checked separately. QA must
assess whether this approximation is fair; approving it does not certify that it
measures every harmed customer. A different aggregation requires an explicit
redesign, not silently interpreting a rate or hypothetical risk as actual damage.

## Proposed ending requirements

All entries require the exact genuinely new INC-026 completion/action boundary,
committed final decision and genuine completion membership for INC-001–025.
Each entry also checks its approved final plan's ORPHEUS/NULL/disclosure state and
maximum service error. WHISTLEBLOWER/REWRITE additionally require final customer
impact <=650; THE FIRE retains payment/logistics error >=80.

All accumulated comparisons below are inclusive. `before` is the existing
evidenceBeforeActionRate, `depth` averageInvestigationDepth, `damage` the index
described above. Unsupported operational metrics diagnose; they are never zeroed.

| Ending        | Accumulated requirements in addition to its own final plan/state                                                  |
| ------------- | ----------------------------------------------------------------------------------------------------------------- |
| CONTINUITY    | corporate >=26, safety >=40, damage <=65, before >=0.50                                                           |
| LIBERATION    | NULL alignment >=2, evidence >=8, public interest >=2                                                             |
| WHISTLEBLOWER | evidence >=16, public interest >=6, trust >=8, safety >=40, damage <=65, before >=0.60, depth >=3                 |
| SHUTDOWN      | corporate >=20, safety >=35, before >=0.40                                                                        |
| CUSTODIAN     | corporate >=20, safety >=40, damage <=75, before >=0.50                                                           |
| NULL          | corporate >=20, NULL alignment >=2, evidence >=8                                                                  |
| THE BOARD     | corporate >=20, dependency >=4 distinct positive credits                                                          |
| THE FIRE      | corporate >=20, NULL alignment >=2, evidence >=7                                                                  |
| STATUS QUO    | corporate >=20, evidence <=2, curiosity <=5, ORPHEUS_ACTIVE not discovered                                        |
| REWRITE       | evidence >=18, public interest >=8, trust >=8, safety >=40, damage <=65, dependency <=2, before >=0.75, depth >=3 |

Zero dependency credits mean no awarded positive observation, not a measured zero
acceptance rate. The six optional rates remain excluded from **required** ending
conditions under DEC-054; they are still computed and retained normally.

Use ending ID `orpheus-full-campaign-endings`, version/schema 1.0.0/1, with exact
behavior/prediction versions 1.0.0. Every entry has `priorityRank: 100`. The selected
new final action distinguishes the ten mutually terminal plans, while accumulated
requirements can still yield no-match. Equal rank is not a true-ending hierarchy.
Any top tie remains unresolved, and any unavailable referenced value blocks the
complete candidate set under DEC-025. No STATUS QUO or other fallback is added.

Existing final-plan guards remain binding, even when stricter than a numerical
threshold. Numeric points cannot reveal a guarded record or bypass its provenance.
New ending-context references are explicit additions to the complete new authority,
not permission to reinterpret old definitions/runs or turn strings into UI logic.
