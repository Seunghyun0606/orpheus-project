## rcedit acquisition and export configuration

No rcedit executable was found on PATH or configured in the existing Godot editor settings.
Downloaded the official [electron/rcedit v2.0.0 release](https://github.com/electron/rcedit/releases/tag/v2.0.0):

```text
URL:     https://github.com/electron/rcedit/releases/download/v2.0.0/rcedit-x64.exe
Path:    .qa/tools/rcedit/rcedit-x64.exe (ignored)
Version: Rcedit v2.0.0 (confirmed by --help)
Bytes:   1,360,384
SHA-256: 3E7801DB1A5EDBEC91B49A24A094AAD776CB4515488EA5A4CA2289C400EADE2A
```

The initial download used Python urllib over HTTPS. PowerShell `Invoke-WebRequest` failed on
this host with an unexpected TLS receive/connection closure, including with TLS 1.2 enabled.
The Node `fetch` command now documented in README was exercised separately and produced the same
SHA-256. The hash above is locally calculated; the release API supplied no asset digest.
Ignored provenance is recorded in `.qa/tools/rcedit/provenance.json`.

The brief's assumption that Godot requires rcedit to embed an icon does not apply to the installed
4.7.2 exporter. It modifies executable resources natively; see the official
[Windows export properties](https://docs.godotengine.org/en/stable/classes/class_editorexportplatformwindows.html).
The final build uses Godot's native icon/version handling and invokes rcedit after export only
to explicitly clear `CompanyName`, `LegalCopyright` and `LegalTrademarks`. `RCEDIT_BIN` overrides
the ignored default path for that build process. No editor settings or tool binary are committed.

An initial experiment reapplied the ICO using rcedit `--set-icon`. Resource-level validation
caught two icon groups: Godot's named group retained stale resource indices after rcedit added
a numeric group. The associated icon pixels then failed comparison. That experiment was
discarded and the executable rebuilt from the original template. The final helper never invokes
`--set-icon`; the final executable has one consistent group, with every image payload matching
the corresponding source ICO entry byte-for-byte.

Godot embeds its six supported sizes (16, 32, 48, 64, 128, 256); it omits 24px during native
conversion. The delivered `godot/icon.ico` contains all seven sizes required by the brief, and
the runtime native icon setting uses that source ICO. No custom exporter was added to force
an additional executable resource size.

The shared `editor_settings-4.7.tres` SHA-256 was identical before and after the work:
`D3E1C62E3A30CB58632AA593BF974C68E59C5DAC2C81DF0BDD59C7E81553F2BD`.
